# Software Design Document: Underhood
**Path:** `docs/sdd/architecture.md`
**Last Updated:** 2026-08-21 (rev. 3 — pg-boss concurrency, entity-aware dedup embeddings, prompt cache, Langfuse observability)

## 0. Scope Decisions (Immutable)
* **MVP Input Scope:** A single code snippet or single source file. Multi-module / whole-repo dependency analysis is explicitly **post-MVP** and must not be implemented until a new SDD revision authorizes it.
* **User-Facing Mode Switch:** The end user makes exactly one visualization choice: **2D or 3D**. No other mode toggles are exposed.
* **LLM Provider Abstraction:** Model access is routed through Mastra's model routing with an OpenAI-compatible interface. Default is OpenAI GPT; Groq (or any OpenAI-compatible endpoint) must be selectable purely via environment configuration (`MODEL_PROVIDER`, `MODEL_ID`, `MODEL_BASE_URL`, `OPENAI_API_KEY` / `GROQ_API_KEY`). No provider-specific code may leak into workflow steps.
* **Plain-Language Requirement:** Every node carries a `plainDescription` (jargon-free, one-to-three sentences) surfaced as a hover tooltip/toast in both 2D and 3D renderers. This serves product people, junior developers, and non-coders.
* **Docker-First Testability:** The project must run end-to-end inside Docker (`docker compose up --build`) on any machine, requiring only that the operator copy `env.example` to `.env` and fill in keys. Compose includes app service(s), a PostgreSQL service, and a reverse proxy for replica parity.
* **Secrets Contract:** `env.example` (variable names + placeholder values only) is a mandatory deliverable of project scaffolding. `.env` is gitignored; agents are forbidden from reading its contents at any time.

## 1. High-Level Mission
The terminal objective of this system is to parse raw user-provided source code, deterministically extract its semantic execution topology, and render it into a hybrid 2D/3D visualization using a robust, stateful AI workflow. "Done" is defined as a system that can successfully ingest a code file in any language, cache the generated JSON topology in PostgreSQL, serve many users concurrently through an asynchronous job pipeline, and render the output on the Next.js client without schema validation errors.

## 2. System Architecture & Boundaries
The architecture is an end-to-end TypeScript monorepo utilizing the Bun runtime.

* **Frontend:** Next.js (App Router) integrating `@xyflow/react` for 2D flowcharts and `3d-force-graph` for WebGL 3D execution tracing.
* **Backend:** Bun server exposing type-safe endpoints; stateless and horizontally scalable.
* **Orchestration:** Mastra (`@mastra/core`) is the sole agent framework. The workflow is built using `createWorkflow` and `createStep` primitives.
* **Persistence:** PostgreSQL is used as the global storage layer via `@mastra/pg`. Mastra's `PostgresStore` persists durable workflow snapshots (suspending and resuming runs), agent memory, observability traces, and eval scores. pg-boss shares this same instance for job queuing (§5).

## 3. Data Models & Schemas
All data validation and schema definitions must use Zod. These schemas act as the single source of truth for both the Mastra workflow's `inputSchema` / `outputSchema`, the database layer, and the frontend API client.

### 3.1 Graph Topology Schema
The core payload generated by the Mastra workflow and sent to the visualization engines.
```typescript
import { z } from "zod";

export const NodeSchema = z.object({
  id: z.string(),
  label: z.string(),
  type: z.enum(["entry", "process", "io", "branch", "terminal"]),
  plainDescription: z.string().describe("Jargon-free, 1-3 sentence explanation of what this node does, understandable by non-coders"),
  metadata: z.record(z.any()).optional()
});

export const EdgeSchema = z.object({
  id: z.string(),
  source: z.string(), // Must map to a valid NodeSchema id
  target: z.string(), // Must map to a valid NodeSchema id
  animated: z.boolean().default(true)
});

export const GraphTopologySchema = z.object({
  nodes: z.array(NodeSchema),
  edges: z.array(EdgeSchema),
  detectedPatterns: z.array(z.string())
});
```

### 3.2 PostgreSQL Cache Schema (Prisma/Drizzle)
```typescript
export const GraphCacheSchema = z.object({
  codeHash: z.string().describe("SHA-256 hash of the raw source code"),
  language: z.string(),
  topologyPayload: GraphTopologySchema,
  embedding: z.array(z.number()).optional().describe("Entity-aware representation embedding for similarity dedup (§6.2)"),
  createdAt: z.date()
});
```

### 3.3 Job Status Schema (Async API contract)
```typescript
export const JobStatusSchema = z.object({
  jobId: z.string(),
  status: z.enum(["queued", "running", "completed", "failed"]),
  topology: GraphTopologySchema.optional(), // present when status === "completed"
  error: z.string().optional()              // present when status === "failed"
});
```

## 4. Interface Contracts & Workflow Steps
The backend exposes the Mastra durable workflow to the Next.js frontend. The workflow is divided into discrete execution steps using `createStep`.

### 4.1 Mastra Execution Steps
1. **`analyzeCodeStep`**: Parses `rawCode` and extracts AST/structural logic.
2. **`generateTopologyStep`**: Invokes the LLM to generate the JSON topology. Must output strictly to the `GraphTopologySchema`.
3. **`validateGraphStep`**: A pure TS validation step. Verifies that all `edge.source` and `edge.target` values exist in the `nodes` array.
4. **`selfHealBranch`**: Triggers if validation fails. Injects the Zod error into the context and retries (maximum of 2 retries).

## 5. Concurrency & Distribution
The system targets concurrent multi-user usage on commodity single-machine deployments (e.g., a $5-tier Railway box) with a simple distribution model.

### 5.1 Job Queue (pg-boss)
* All analysis work is asynchronous. `POST /analyses` validates input, enqueues a job via **`pg-boss`**, and immediately returns `{ jobId }`.
* `GET /analyses/:jobId` returns `JobStatusSchema` (§3.3).
* **pg-boss lives inside the existing PostgreSQL instance** — no additional database, broker, or Redis. Its schema is created together with the database implementation (same migration/wiring step as the Mastra store).
* An in-process worker pool pulls jobs with concurrency configured by `WORKER_CONCURRENCY` (default 4). Each job executes the Mastra workflow from §4; durable snapshots make jobs resumable across restarts and deploys.

### 5.2 Stateless Replicas
* The app holds zero session state — all state is in PostgreSQL. Any instance can serve any request.
* Horizontal scaling = N replicas behind a load balancer: Railway's native LB in production; a Caddy reverse-proxy service in docker-compose for local parity.
* Per-instance caps (`WORKER_CONCURRENCY`) provide backpressure so a small machine degrades gracefully instead of collapsing under LLM latency.

## 6. Caching, Dedup & Observability

### 6.1 Prompt Cache
Postgres table keyed by `(promptHash, modelId)` → cached completion payload. Hash = SHA-256 of the fully rendered prompt string + model id. Cache hits skip the LLM entirely for identical prompts.

### 6.2 Entity-Aware Similar-Snippet Dedup (Embeddings)
* After `analyzeCodeStep`, the system builds an **entity-aware normalized representation**: an AST-derived structural skeleton preserving entity names (functions, variables, parameters) alongside control-flow shape.
* This representation is embedded via the provider-routed embedding endpoint (`EMBEDDING_MODEL`) and stored on the topology cache entry (§3.2).
* On new submissions, cosine similarity against cached embeddings above `SIMILARITY_THRESHOLD` returns the existing validated topology instantly — even when code differs superficially (reordering, formatting). Cached entries keep their real entity names so deduped results display meaningful, ludic labels for non-coders.
* Embedding calls are themselves subject to an embedding-cache table (`inputHash, EMBEDDING_MODEL` → vector).

### 6.3 Observability (Langfuse Cloud)
* Mastra's native observability exports to **Langfuse Cloud free tier** via the official `@mastra/langfuse` `LangfuseExporter`.
* Captured automatically per trace: full span timeline of workflow steps and agent iterations, **token usage, cost data, and timing**.
* Eval scores persist to Postgres observability storage and appear in Langfuse traces only — no UI surface.
* Credentials come exclusively from env (`LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, optional `LANGFUSE_BASE_URL`). Absent keys ⇒ tracing disabled; the app must run without it.

## 7. Runtime Environment & Deployment Contract

### 7.1 Required Environment Variables (`env.example`)
```bash
# --- Model routing (OpenAI-compatible abstraction) ---
MODEL_PROVIDER=openai            # openai | groq
MODEL_ID=gpt-4o                  # any model id valid for MODEL_PROVIDER
MODEL_BASE_URL=                  # optional override (e.g. https://api.groq.com/openai/v1)

# --- Keys (fill in .env only; never commit) ---
OPENAI_API_KEY=
GROQ_API_KEY=

# --- Persistence & queue ---
DATABASE_URL=postgres://postgres:postgres@db:5432/underhood
WORKER_CONCURRENCY=4

# --- Dedup embeddings ---
EMBEDDING_MODEL=text-embedding-3-small
SIMILARITY_THRESHOLD=0.95

# --- Observability (Langfuse Cloud; leave blank to disable tracing) ---
LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=
LANGFUSE_BASE_URL=

# --- App ---
PORT=3000
NODE_ENV=development
```

### 7.2 Docker Topology
* **App service:** multi-stage `Dockerfile` on a Bun base image; builds monorepo and runs backend + Next.js frontend; replica-ready (stateless).
* **DB service:** PostgreSQL 16 with a named volume; healthcheck-gated so the app waits for readiness.
* **Proxy service (local parity):** Caddy reverse proxy fronting N app replicas.
* **Acceptance:** `docker compose up --build` on a clean machine yields the end-to-end demo (paste code → select 2D or 3D → rendered graph) using only `.env` values from `env.example`, surviving multiple simultaneous submissions.

## 8. Constraints & Anti-Patterns
To prevent agent drift and ensure system stability, the following rules are immutable:
* **No Python Ports:** LangChain and LangGraph are explicitly banned. Use only TS-native Mastra APIs.
* **No Manual Type Duplication:** The frontend must consume the Zod schemas directly from the backend shared package.
* **No Shadow Databases:** All state — workflow snapshots, eval scores, caches, and the pg-boss queue — lives in the single PostgreSQL instance via `@mastra/pg`. Do not use in-memory SQLite (`libSQL`) or Redis for production state. PostgreSQL is wired from the first pipeline goal (Goal 2), not deferred.
* **No Direct Canvas Generation:** AI agents are forbidden from calculating X/Y visual coordinates for nodes. All layout math is delegated to Dagre/ELK on the client side.
* **No Provider Coupling:** Workflow steps must never import provider SDKs directly. All model calls go through the Mastra model-routing abstraction configured via environment variables (see §0).
* **No Secret Access:** Agents must never read `.env`. Secrets are supplied by the human operator; agents only create and maintain `env.example`.
